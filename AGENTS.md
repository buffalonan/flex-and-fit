# AGENTS.md

Context for AI agents and reviewers working on this repo. Read this first instead of re-deriving it from the code. Keep it up to date when you change how things work.

## What this is

Flex & Fit: one person's log of gym workouts and flexibility sessions (Ferran, who writes in Spanish; the UI is in Spanish). A web app served by his Mac and the same app wrapped for Android (Samsung S23) with Capacitor. Modelled on `buffalonan/german-learning`: no framework, no build step, every merge to `main` releases the APK and the Mac's image.

**Roadmap** (proposal doc: https://claude.ai/artifact/91xtGjZy26UdwRYwkTv3kG):
1. Skeleton and releases: quick session log, history, sync with the Mac, JSON backups. Done.
2. Workouts with the design guide (https://claude.ai/artifact/CkekWik1jW3c5HiwC4w247): the 6-month flexibility plan with animated SVG figures and a stretching player, Ferran's four Coros gym workouts with a basic set logger, a 10-exercise kettlebell workout (`kb`: halo, swings, one-arm press, etc.), professional templates (StrongLifts 5×5 A/B, ACSM beginner full body: structure only, with a `fuente` link, listed apart under "plantillas profesionales"), the mannequin, progress (calendar, monthly test) and profile. Lottie and 3D prototypes are kept in `prototypes/animaciones/`; the realistic 3D mannequin (`maniqui-3d-realista.html`, approved by Ferran) is now the app's big figure.
3. Gym in depth: history per exercise, records, editing workouts. **Health Connect**: done (see "Watch" below). Training load and HRV are not in Health Connect.
4. Progress charts per exercise.

**Workout UX (Ferran's requirement):** home is a list of workouts as cards; tapping one shows its exercises (animation, dose, cues) and a start button. Each workout shows a body mannequin, front and back, modelled on the Coros app: grey silhouettes on a dark panel, worked muscles in red, stronger with more sets, each with a dotted leader label ("9 series"), and stats below (series, tiempo, FC media, kcal, carga). Exercises carry their primary and secondary muscles; a workout's map is the sum of its exercises'.

## How it works

- **Records:** every piece of data is a record `{ tabla, id, data, actualizado, borrado }`. Tables: `ejercicios`, `sesiones`, `series`, `tests`, `rutinas`, `ajustes` (the server refuses others; add new ones in `server/db.js` `TABLAS`). Ids are UUIDs, or stable ids such as `plan-<fecha>` and `fase-<n>` for imported plan data. Deleting sets `borrado` so the delete syncs.
- **Local first:** `store.js` keeps records in IndexedDB (`flexfit` database, stores `registros` and `meta`). A local write sets `pendiente: 1`. `store.onChange` re-renders and schedules a sync 1.5 s later.
- **Sync** (`sync.js`, `POST /api/sync`): the device sends its pending records and `desde` (the last server `seq` it saw); the server applies them (newest `actualizado` wins, a tie keeps the server's) and returns everything with `seq > desde`, in pages of 5000 (`mas: true` means ask again). The device clears `pendiente` only on records not edited again meanwhile, applies what came back with the same rule, and stores the new `seq`. Syncs run on start, after changes, every 5 minutes, when the browser comes online and when the app resumes. `SYNC_TOKEN`, if set on the server, must be sent as `Authorization: Bearer`.
- **Where the server is:** the web served by the Mac uses its own origin; the Android app has no default and finds the Mac itself (`direccion.js`): it keeps the addresses it knows in `localStorage` (`servidor` in use, `servidores` up to 6), and when the one in use doesn't answer it tries the others with `/api/salud` and keeps the first to answer; with none, it looks for the Mac's Bonjour announcement `_flexandfit._tcp` on the Wi-Fi (the local plugin `DescubrirPlugin.java`, Android NsdManager; at most once a minute, or on Perfil → Buscar el Mac). `/api/salud` returns `direcciones` from the server's `DIRECCIONES` env, which the Mac's `update.sh` rewrites in `.env` every hour (Wi-Fi and Tailscale IPs), so the phone learns the Tailscale address at home. The address can still be typed in Perfil; the Pages demo has none, hides the server card and keeps data in the browser. **Never commit the owner's host names, Tailscale IPs, ports of other services or personal paths:** the repo and the Pages demo are public.
- **Under a sub-path:** the Mac's reverse proxy can serve the app at `http://<mac>/fitness/`, stripping the prefix before it reaches port 3334, so the server only ever sees `/`, `/app.js`, `/api/...`. Every URL in `web/` is relative (never `/something`); a tiny inline script in `index.html` turns `/fitness` into `/fitness/` first; the web's server is the page's folder (`new URL(".", location.href)`), not its origin; and addresses (`origen()` in `direccion.js`, `DIRECCIONES` on the server) keep their path, so the phone can use `http://<mac>/fitness` too. A test runs the app behind such a proxy.
- **Android and plain HTTP:** the app's WebView origin is `https://localhost`, so `CapacitorHttp` is enabled in `capacitor.config.json` to send `fetch` natively, and the manifest allows cleartext. Tailscale encrypts the traffic.
- **Backups:** the server checks every hour and writes `flexfit-YYYY-MM-DD.db` (`VACUUM INTO`) into each `BACKUP_DIRS` folder whose newest copy is 7+ days old, keeping 12. On the Mac these are `~/Documents/fitness-backups/weekly` and Google Drive's `Backups/Fitness`. JSON export/import in Perfil covers every record; import also takes the JSON copied from the 6-month flexibility plan artifact (`plan: "flexibilidad-6m-v1"`).
- **UI:** always dark (design guide). Four tabs at the bottom: Entrenos (today's routine on top, then the gym workouts and the plan's routines F1–F6 and "suave", filter Todos/Fuerza/Flex), Progreso (week counts, 5-week calendar, monthly test form and chart), Historial (sessions, plus a form to log one by hand; tapping a session opens `#sesion`: mannequin of what was done, stats with the watch's FC media/máx and kcal, the heart-rate chart from `reloj.curva` with a touch cursor, volume per exercise, each exercise's sets and its progression over the last 8 times it was done, by heaviest kg, or reps/time when bodyweight) and Perfil (plan start date, server, backups). Tapping a card opens its detail (`#detalle`); tapping one of its exercises opens its sheet (`#ficha`: the big animated figure, dose and cues for a stretch; the figure, mannequin, dose, rest, cues and last time for a gym exercise; previous/next and EMPEZAR); EMPEZAR opens the full-screen stretching player (`#reproductor`) or the gym logger (`#registro`), and the end shows a summary (`#resumen`). The sync pill at the top shows Sincronizado, "N sin subir", "Sin conexión con el Mac" or "Solo en este dispositivo". `renderSync` drops overlapping renders so a stale read never wins. Settings live in `localStorage` under `flexfit.ajustes` (`servidor`, `servidores`, `token`, `tab`, `filtro`), always in try/catch. Android Back closes panels and the exercise sheet, leaves a session (asking first) or the detail, goes to Entrenos, and closes the app from there.
- **Plan:** the start date is the record `ajustes/plan-flexibilidad` (`inicio`), set in Perfil, by the plan's JSON import, or by the first plan session done in the app. `enPlan()` gives the week, phase and today's routine (Sunday is "suave"; the last Sunday of a phase is test day). A stretching session is saved as `sesiones/plan-<fecha>` (same id as the plan import, one per day) with `ejercicios: [{ id, dosis, hecho }]`; monthly tests as `tests/fase-<n>`.
- **Player:** `pasos()` turns a dose ("1 × 60 s /lado", "2 × 8", "3 ciclos /lado", "5 cambios + 30 s /lado") into timed steps (Ferran asked for the 2 × 30 s holds to be one continuous minute, 2026-11-26); reps are timed at the exercise's `ritmo`. Prep steps of `PREP_SEG` (10 s, in `datos.js`) go between them (get ready, change side, breathe between sets; Ferran found shorter ones too short, 2026-11-26). A routine's `min` is computed from its steps and pauses (`duracionMin()`), never typed; Ferran wants sessions of at least half an hour, so F1–F4 were lengthened to ~31 min (F5 34, F6 41, Sunday ~10) and a test keeps every phase at 30+ min. Sound cues (`avisos.js`, Ferran asked for soft harp sounds, not repeated beeps): "pronto" (a falling pair) 3 s before any step of 8 s or more ends (a stretch, or the 10 s rest before the next one), "acaba" (falling arpeggio, vibrates) at its end, "empieza"/"lado" (rising arpeggio, vibrates) when the next stretch starts; the rest timer gets "pronto" 5 s before (rests of 20 s+) and "empieza" at 0. `programarAvisos()` in `app.js` works out the whole list again on every timing change (step, pause, skip, rest ±15 s); in the app it goes to `EntrenoPlugin.pitidos()`, which plays it natively (`Pitidos.java` synthesises the same notes and partials with AudioTrack, media volume) so it sounds with the phone locked; in a browser `avisos.tick()` plays it with Web Audio. A step that ends on its own hands its exact end time to the next (`irA(i, desde)`), so after the web view was frozen the player catches up with the clock and the cues already played. Tests: `tests/avisos.spec.js`. The player and logger keep the screen on (`FLAG_KEEP_SCREEN_ON` in the app, the Wake Lock API asked for again on every return to the page in a browser), and Saltar jumps to the next exercise; a stretch counts as done only if one of its steps ran to the end.
- **Gym exercises** (`GYM` in `datos.js`): `series`, `reps` or `seg`, `kg` (null = bodyweight), `desc` (rest), muscles `p`/`s`, optional `porLado` (reps per arm/side: shown as "/lado", counted twice in the volume) and `c` (how to do it, shown in the exercise sheet).
- **Gym logger:** one page per exercise (a circuit is one page with its rounds), with last time's kg and reps filled in (`ultimasSeries()` in `app.js`): from the newest gym session of that workout where at least one set of that exercise was ticked, matched by name (and order, for same-named ones); failing that, the kg (not the reps) from the newest time in another workout. The exercise sheet's "La última vez" uses the same. Changing a set's kg carries the new weight to that exercise's later sets not ticked yet (in a circuit, its later rounds). Kg may be negative (assisted pull-ups on the machine): the kg field has no `min`, and since the phone's number keyboard has no minus key, bodyweight exercises (`corporal()`, or any set already negative) get a ± button beside the kg (`celdaKg()`/`cambiarSigno()` in `app.js`, in the logger and in `#editar`; it looks pressed while negative, and the flip carries to later sets like a typed weight). Negative kg add nothing to the volume. Ticking a set starts its rest timer (±15 s), with its sound cues (see Player). A gym session is `sesiones/<uuid>` with `rutina` (g1–g4, or a template id), `volumenKg` and `ejercicios: [{ n, series: [{ kg, reps | seg, hecho }] }]`.
- **Cardio** (`CARDIO` and `CAMPOS_CARDIO` in `datos.js`): elliptical, treadmill, exercise bike, rowing, stair climber, other; each machine lists the fields its display shows (distance, speed, incline, level, kcal), all optional but the minutes. Added on the fly in the gym logger (`#regCardio`, under the sets on every page: before any set is ticked it defaults to "antes", after to "despues"), or from the summary (`#resCardio`, saved on the session at once), in `#cardioPanel`; tap a block to change it, ✕ to remove it. Editing a past gym session (`#editar`) changes its cardio too (`#edCardio`, written on Guardar). Stretching sessions take it too: `#repCardio` in the player (opening the form pauses it; labels say "antes/después de estirar"), the summary and editing; a second plan session the same day keeps the day's earlier cardio. Saved as `cardio: [{ tipo, momento, min, km?, kmh?, incl?, nivel?, kcal? }]` on the session (and in `flexfit.enCurso` while training). Kept out of the volume, records, progression and mannequin; shown in Historial ("cardio N min"), the session detail's stats and `#sesCardio`. A new machine is one line in `CARDIO` plus its name in the dictionaries. Tests: `tests/cardio.spec.js`.
- **Records and progression** (own rules, from the sets saved): `e1rm()` is Epley's estimated 1RM (sets of 1–12 reps with weight). `mejorDe()` gives an exercise's best (estimated 1RM and its set, heaviest kg, or most reps/seconds with no weight; negative kg count for neither); `records(s)` lists what session `s` beat against every gym session before it (none the first time). Records show in the summary (`#resRecords`), as a chip in the session detail, in Progreso (`#records`) and in the exercise sheet ("Tu récord"). `subida()`: when last time in the same workout every set was ticked at the target reps/time or more, the logger starts one step up (+2.5 kg, assisted 2.5 kg less help capped at 0, or +1 rep / +5 s with no weight) and says why (`#regSube`); not applied to values coming back from a session in progress. Progreso's `#musSemana`: sets per muscle since Monday (primary full, as the mannequin), bars scaled to 20 with a mark at 10. The summary asks how hard it felt (`#resEsf`, 1–10), saved as `esfuerzo` on the session and shown in its detail. Tests: `tests/fuerza.spec.js`.
- **Deleting a session** (Historial's "Borrar"): asks first (`#borrarPanel`, `pedirBorrar()` in `app.js`), then keeps a copy of the session in this device's meta `papelera` (`[{ id, data, borrada }]`, newest first, 30 days, at most 50; never synced) before `store.remove`, because a delete syncs an empty record and the content would be gone everywhere. Perfil → "Sesiones borradas" (`#papeleraCard`, only when there is one) lists them; Recuperar writes the data back with a newer `actualizado`, so it wins on the Mac too. If a session was deleted on a device without a bin, its old JSON may still be in the free pages or WAL of the Mac's SQLite file: copy `/data` out of the container with `docker cp` before opening it, and put it back through `POST /api/sync` or Perfil → Importar JSON with a newer `actualizado`. Tests: `tests/borrar.spec.js`.
- **Editing a past session** (`#editar`, "✎ Editar la sesión" in `#sesion`; `abrirEdicion()`/`guardarEdicion()` in `app.js`): a copy of the session is edited and written only on GUARDAR, over the record as it is then (so watch updates meanwhile aren't lost). Gym: each set's kg, reps or seconds and tick, remove or add sets (a new one copies the last), swap an exercise for another (its sets stay; `seg` or `reps` follows the new exercise's definition), remove exercises, add one from any workout; stretching: mark each exercise done or skipped; both: minutes and notes. `volumenKg` is summed again; `reloj`, `relojNo`, `esfuerzo`, `inicio`/`fin` stay. Records, progression, the logger's last time and the week's sets are computed from the saved sets, so they follow. Sets written into a watch-only session drop its `origen: "reloj"`, so it becomes a session of its own with the watch kept. The date isn't editable (plan sessions' ids carry it). Tests: `tests/editar.spec.js`.
- **Body weight** (`ajustes/peso`: `{ pesos: [{ fecha, kg, origen }] }`, one per day, oldest first): read from Health Connect (`READ_WEIGHT`, `SaludPlugin.peso()`, any source: a scale, Samsung Health, COROS) on every watch read once allowed (Perfil → "Leer el peso de Health Connect" asks for it), or typed in Perfil (`origen: "mano"`, which a Health Connect reading of the same day doesn't replace). `unirPesos()` in `reloj.js` merges them. `pesoEn(fecha)` gives the weight on a day (latest on or before it, else the first after). Uses: relative strength (1RM ÷ weight, "0,71× tu peso") in Progreso's records and the exercise sheet; the volume of bodyweight exercises (`corporal(def)`: `kg: null`, not `elige`, not timed) counts weight + kg (negative = assistance) per rep, in the logger's summary and the session detail (whose total is now always summed from its sets); Progreso's `#pesoGraf` charts the last 6 months. Tests: `tests/peso.spec.js`.
- **Session in progress** (Android may close the app with the phone locked): every change in the player or logger (and going to the background) writes the open session to `localStorage` `flexfit.enCurso` (gym: `valores`, `pag`, `desc`; flex: `idx`, `hechos`, `seg`; plus `rutina`, `inicio`). It's this device's only, never synced, and removed when the session is saved or discarded. On start, `ofrecerContinuar()` shows `#continuarPanel`: Continuar (a gym session comes back as it was; a stretching one paused at the start of its step), Guardar lo hecho, Descartar. A saved session that no longer fits the workouts is dropped. While one is pending, the watch import doesn't make watch-only sessions. In the app, `EntrenoPlugin` runs a `specialUse` foreground service with an ongoing notification (chronometer from `inicio`, tap opens the app) from `entrar()` to `salirSesion()`, so Android is less likely to close it; it asks for `POST_NOTIFICATIONS` (Android 13+) the first time. Tests: `tests/en-curso.spec.js` (a reload is the app reopening).
- **Mannequin** (`maniqui.js`): front and back, half shapes mirrored. Strength: primary muscles red, secondary amber (as in Coros), labels "N series" for the primary ones. Flexibility: teal by minutes (< 1, 1–3, 3+), primary muscles count their full time and secondary ones half.
- **Figures** (`figura.js`): each stretch has a start pose and a stretch pose in joint angles; the figure rests on the floor on its own, eases into the stretch, breathes, and lights up where you feel it. Props (wall, door frame, towel, cushion) follow the pose. Strength exercises have figures too (`G` in `figura.js`, mapped by exercise name in `FIG_FUERZA` in `datos.js`, shown in the workout's list, the exercise sheet and the set logger): hands and feet are placed with two-bone IK (`m1`/`m2`, `p1`/`p2`), `fijo` pins a joint (feet on the floor, hands on a bar, hips on a bench), `peso` draws the kettlebell, dumbbell, barbell, sled or pad, `obj` the benches and machines, `cable` a pulley (`[x, y, "manos"]` ends between the hands, on a bar or handle; `"cuerda"` is a rope whose two ends are in each hand, as in the face pull and the triceps pushdown), and `fr` keyframes the movements that aren't a back and forth (halo, Turkish get-up). A new strength exercise needs an entry in both.
- **3D figure** (`figura3d.js`, loaded lazily by `en3d()` in `app.js`): the exercise sheet, the stretching player (in its ring, no buttons) and the set logger show the 3D mannequin (red shirt, white shorts and shoes, uniform face, own design: never COROS assets), with angle buttons under it (Frente, ¾, Lado, Espalda, Arriba) and drag to turn; lists keep the small SVG. It reuses the SVG poses: `estado()` in `figura.js` gives the 2D joints, `posar()` maps them to 3D (side view x → depth, front view x → sideways, 0.0147 m per SVG unit) and places arms and legs with two-bone IK; `ESPECIAL` has hand-made 3D poses (halo, supine twist, 90/90); props and weights come from the 2D `obj`, `peso` and `cable`. Muscles light up as gradients painted on skin and clothes (no patches), primary red, secondary amber, stretches teal. There is one WebGL canvas, moved between hosts; the one it leaves gets its SVG back. Without WebGL the SVG stays. `revisar(id)` checks every frame (no NaN, nothing under the floor, hands where the 2D figure has them, both hands on the cable) and a test runs it for every figure. Playwright launches Chromium with SwiftShader for WebGL, and tests switch WebGL off unless they ask for it (`abrirApp(page, time, { webgl: true })`).

- **Language** (`i18n.js`, `idiomas/en.js`, `de.js`, `ca.js`): Spanish is the source and the default. Every text is written in Spanish in the code and in `datos.js`, and shown through `t("…")` (with `{name}` placeholders, `tn(n, singular, plural)` for plurals, `dosis()` for a plan dose's words, `num()` for decimals, `locale` for dates); each dictionary maps the Spanish text to its translation, and a missing one shows in Spanish (and is recorded in `faltan`). Static texts in `index.html` are translated on load by `traducirPagina()` (whole text nodes and `aria-label`/`placeholder`/`title`), so the markup stays in Spanish. The language is picked in Perfil (Español, English, Deutsch, Català), kept in `flexfit.ajustes.idioma` on this device only, and applied by reloading. Records keep their Spanish names (gym exercises are matched by name), so only what's shown is translated; the watch's own workout titles are not. **A new or changed Spanish text needs its entry in all three dictionaries**: `tests/idiomas.spec.js` walks every screen in each language and fails on a missing translation, on Spanish left on screen, and on sideways scrolling (German is long).
- **Watch (Health Connect)** (`reloj.js`, `SaludPlugin.java`): Android 14+ only, with the platform `android.health.connect` API (no extra library). Perfil → "Reloj · Health Connect" asks for the read permissions (exercise, heart rate, total and active calories, weight). The app reads the last 30 days of exercise sessions on start, on resume, every 2 minutes (at most once a minute) and right after a session (and a minute later); only gym-like (`fuerza`: strength, weightlifting, calisthenics, HIIT, boot camp), stretching-like (`flex`: stretching, yoga, pilates) and `otro` types; runs and walks are ignored. For each: average/max HR from the samples inside it (the same app's first, else any source) and kcal from the same app only (total, else active). `emparejar()` joins each to one app session: overlapping times (±15 min) first, then the same day, closest first (a session logged by hand, or logged in the app before or after the watch workout), matching gym ↔ `fuerza`, flexibility ↔ `flex`, `otro` either way. A watch stopped and started again: another free `fuerza`/`flex` piece the same day within 60 min of a session's watch time joins it too; `combinar()` makes one `reloj` from several (`partes` keeps each; first start to last end, HR weighted by time, kcal added, curves on one timeline). The session detail (`#sesReloj`) joins a watch-only workout to a session by hand (`unirA()`, sessions of that day ±1) and separates a piece (`separar()`: it goes back as `reloj-<id>` and its id goes to the session's `relojNo`, so it never joins that session again). Durations show the longer of the logged minutes and the watch's. It writes `reloj: { id, inicio, fin, categoria, fcMedia, fcMax, kcal, curva, curvaPaso, titulo, origen }` on the session (`curva`: average HR per `curvaPaso` seconds, a minute or longer so there are at most 180 points, 0 where there's none). A `fuerza`/`flex` workout with no session becomes `sesiones/reloj-<id>` with `origen: "reloj"` ("Solo en el reloj" in Historial) until a session logged later takes it (then that record is deleted). Watch ids already handled are in meta `relojVistos`, so a watch-only session the user deletes isn't made again. App sessions now save `inicio` and `fin` (ms). While training, the player and logger show the latest HR if the watch writes it live (COROS normally writes everything when the workout ends and syncs). Tests fake `window.Capacitor` and the plugin (`tests/reloj.spec.js`).
- **App updates** (`actualizar.js`, `ActualizarPlugin.java`): Android app only. On start and on resume (at most every 6 hours; Perfil → Actualizaciones → Buscar forces it) it reads `api.github.com/repos/buffalonan/flex-and-fit/releases` and picks the newest non-draft, non-prerelease `app-v1.<n>` with `flex-and-fit.apk`; `<n>` is the run number, the same as the APK's `versionCode`, so it compares with the plugin's `version()` (or `<meta name="app-version">`). A newer one is offered once in `#actPanel` (not during a session, not in debug builds; "Ahora no" skips that version, Perfil keeps offering it). Actualizar (or Perfil's "Descargar e instalar") makes the plugin's `abrir()` open the APK's link (only `https://github.com/buffalonan/flex-and-fit/releases/download/`) in the browser, which downloads it and hands it to Android's installer; signed with the same key, it installs over the app and keeps the data. **The app must not download or install APKs itself (`REQUEST_INSTALL_PACKAGES`)**: with it, Google Play Protect blocked the sideloaded APK as "Harmful app" (2026-11-25). State in `localStorage` `flexfit.actualizacion` (`comprobada`, `release`, `ignorada`). Keep the release key: an APK signed with another key can't update the app, and Play Protect's trust builds up on that key. Tests: `tests/actualizar.spec.js`.

## Rules

- **Write markup only through the `html` tagged template** in `app.js`; it escapes every value. ESLint's `no-unsanitized` fails CI otherwise. Notes and imported JSON are user input.
- Elements are shown and hidden with `el.hidden` (the `[hidden]` rule in `styles.css` makes that work).
- Colours are CSS variables on `:root` (one dark set: the app is always dark). Tap targets are at least 44px (48px in the design guide). The page must fit a phone without sideways scrolling (a test checks every tab).
- Exercise instructions must be safe and correct: tension, never pain; no bouncing.
- New or changed behaviour needs a test (`tests/` for the app, `server/server.test.js` for the server). Never skip or delete a test to get CI green.
- The server has no npm dependencies on purpose; keep it that way unless there's a strong reason.

## Commands

```sh
npm ci
npm run serve                     # http://localhost:3334, data in ./data
npm test                          # server tests + Playwright
npx eslint . --max-warnings 0
npm run app:sync                  # web → Android project
```

In Claude's cloud sessions use Node 24 (`export PATH=/opt/node24/bin:$PATH`) and `PW_CHROMIUM=/opt/pw-browsers/chromium` for Playwright's browser.

## CI and workflow

- Work on a branch and open a PR into `main`. Don't push to `main` directly.
- `tests.yml`: ESLint, server tests, Playwright. `security.yml`: npm audit, signatures, gitleaks (weekly too). `codeql.yml` and dependency review (public repo). `claude-review.yml`: Claude reviews each PR once against `REVIEW.md` from the base branch, in Spanish, skipping `web/vendor/`, `prototypes/`, lockfiles and binaries (`@claude review` for another look; `@claude` in a comment answers). It needs the repo secret `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`); without it the job passes with a "NOT REVIEWED" step.
- `android.yml`: Android Lint, emulator smoke test, APK on every PR (artifact) and on `main` the release `app-v1.<run>` with `flex-and-fit.apk`, signed with `ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD` or a one-off key if missing.
- `docker.yml`: builds the image for arm64 (the Mac is Apple Silicon, Docker via colima) and amd64; on `main` pushes `:latest` and `:1.<run>` to ghcr.io. The package must be public for the Mac to pull it without logging in.
- `pages.yml`: the demo on GitHub Pages, in two jobs (build, then deploy) so deploy-pages finds the uploaded artifact.
